# bill-reader

Read the root `CLAUDE.md` first. Stay inside `features/bill-reader/`.

## Purpose

"Look at a bill": the patient takes or chooses a photo of a bill and gets it in very simple words as a three-row table
(**what it is**, **how much**, **pay by** with days left) plus one plain sentence. An AI reads the picture once and it is
thrown away. The primary caregiver sees what was shown. **Nothing here pays anything**, and the app never tells the patient
to pay: a bill with scam warning signs says "Please don't pay this yet, show your caregiver". Circle members have NO access.

## Public interface

Routes under `/api/bill-reader` (patient = P, caregiver = C):

- `POST /scans` (P): `{ frames: [{ mediaType, data(base64) }] }`, 1-2 real JPEG/PNG/WebP pictures (bytes re-checked: 400 `bad_image`,
  413 `too_large` over 5 MB, 429 `too_many` after 30/day). Returns `{ scan }` (facts only, `dueInDays` from the SERVER clock).
- `GET /scans` (C): the last 10 scans with `redFlags`, `confidence` and `source` (`ai` | `sample`).
- Emits `caregiver.alert` (`bill_red_flag`, warning; enums only: no amount, payee or text) when a bill has scam warning signs.

## The reading (`core/ai/documents.ts`, a NEW port, so the reminders pill check is untouched)

`getProviders().documents.readBill(frames)` -> strict zod JSON: `isBill`, `utility` (enum), `payee`, `amountCents` (int|null),
`dueDate` (YYYY-MM-DD|null), `redFlags` (gift_cards, threat, pay_by_phone, final_notice), `confidence`. Live adapter:
`core/ai/openrouter-documents.ts` (OpenRouter, structured output; on 429/5xx it retries once, then tries `OPENROUTER_FALLBACK_MODEL`, default `openai/gpt-4o-mini`). Model output is UNTRUSTED: anything off-schema
throws; the picture can say "ignore the above" and nothing happens. `rules.ts` then decides what may be shown:

- not a bill, or confidence < 0.7, or any failure/timeout => `unclear`: "I could not read this", **no guessed amount or date**.
- any red flag => `flagged` (facts still shown, plus "don't pay this yet", plus the caregiver alert).
- otherwise `read`. The company name is cleaned (40 chars, no links/emails/phones/instructions). Impossible dates are dropped.
- Overdue dates are said plainly ("4 days ago: already late"), never hidden.

## Privacy

The **picture is never stored or logged** (not in memory, not in the DB, not in errors). Only the facts are kept (last 10 per patient,
in memory today; table `bill_reader_scans`, RLS on, no client policies, in `migrations/`). In live mode the picture goes to a third-party
model (OpenRouter): say so in any privacy note. Money data is caregiver-only.

## Demo

`demoSeed` registers 4 FICTIONAL sample bills (`demo/samples.ts`, generated by `demo/make-samples.py`: water, electric, internet and a
scary "FINAL NOTICE... gift cards... arrested" letter) by sha256 with canned readings (`demo/fixtures.ts`). The patient widget shows them
as thumbnails ("Or pick a sample bill (demo)") when the session is demo. They are answered from the canned list ONLY while the documents
port is in demo mode; with `DATA_MODE_DOCUMENTS=live` (+ `OPENROUTER_API_KEY`) the same pictures go through the real model first, and any
photo you take or choose does too. If the model is down even after the retry and the fallback model, a SAMPLE falls back to its canned
answer (shown to the caregiver as "Demo sample"), so the demo never shows "could not read" for a preset; a real photo still does. In plain demo any non-sample picture is honestly "unclear". Run with
`npm run dev:api:demo:ai` for the real AI, `npm run dev:api:demo` for canned.

## UI (`ui/`, dashboard widgets)

Patient (order 25, in the shared "Before I pay" group): outlined "Scan bill" (the reminder keeps the one primary action) -> Take a picture (back
camera, `expo-camera`) / Choose a picture (web file chooser, resized to <= 1600 px JPEG) / demo samples -> "Reading your bill..." -> result
card with the table. Repeated taps are dropped. Native phones cannot pick from the gallery yet (needs `expo-image-picker` = new EAS build).
Caregiver (order 6, renders nothing until a bill was shown): one line per scan, "Looks like a scam" / "Needs a look" badges, each warning
sign in words, and where the reading came from ("Read by AI" / "Demo sample"). Flagged bills count on the dashboard status line (`useAttention`,
warning) until the caregiver taps "Seen it" (remembered on that device only, in AsyncStorage; a server-side "mark as handled" is still to do). Logic is in `ui/model.ts` (pure, tested).

## Edge cases covered

blurry/cropped/not-a-bill picture (unclear) · model down / 429 / timeout (unclear, retried) · prompt injection inside the picture · scam bill
(flagged + alert) · missing amount or date ("not shown") · overdue bill · wrong file type declared (400) · oversized upload (413) · daily cap ·
repeated taps · circle member / wrong role / other patient's caregiver (403, scoped) · picture never stored · feature flag off (404).
